# Phase 2 v2.1.1 — Multi-LLM AB-MCTS (`[NOVEL TREE]`) · Design Spec

**Date:** 2026-07-06
**Builds on:** v2.1 conductor (greedy AB-MCTS-lite, benched SUPPORTED 8.50 vs cop-opus 6.50).
**Faithful to:** Sakana AI "Wider or Deeper? Scaling LLM Inference-Time Compute with
Adaptive Branching Tree Search" (arXiv 2503.04412), **AB-MCTS-A** variant + the
**Multi-LLM** bandit extension.
**Author:** Claude Code (brainstorming session, approved by salva).

---

## 1. Goal

v2.1's greedy width/depth loop validated the thesis (committee-of-cheap beats a frontier
single-shot on $/quality). v2.1.1 replaces the greedy heuristics with the **actual
algorithm**: Thompson sampling over a real search tree, plus a Thompson bandit over
**which model** generates each node.

North star (unchanged): **frontier quality (Fable-5 / GPT-5.6 tier) from a mix of tokens
never paid for at frontier price** — free NIM when healthy + cheap paid Zen (GLM 5.2,
DeepSeek) + Copilot credits, blended by the search.

**Cost posture (owner's decision):** paid providers are **first-class arms, not last
resort**. Zen per-token models are cents; Copilot is per-credit. NIM is a free *bonus*
gated by live health. The bandit maximizes **reward**; cost is recorded in the receipt
and may break near-ties, but never gates a capable model out of the pool.

## 2. Non-goals

- Replacing `[NOVEL]` (greedy conductor stays untouched — proven baseline for A/B).
- Learned/persistent bandit state across calls (each call starts from priors; persistence
  is a possible v2.1.2).
- AB-MCTS-M (mixed-model node refinement) — we build AB-MCTS-A only.
- v3 multi-agent workflows.

## 3. Trigger & dispatch

- New tag **`[NOVEL TREE]`** (optionally `[NOVEL TREE DEEP]` etc. — same difficulty
  suffixes as v2.0). `parse_novel()` returns mode `"tree"`.
- `fuse()` dispatches mode `"tree"` → `fusion/abmcts.py::conduct_abmcts()`.
- `[NOVEL]` keeps the v2.1 greedy conductor. Both live side by side; the default flips
  only if the 3-way bench says tree wins.

## 4. Core algorithm (AB-MCTS-A + Multi-LLM)

```
conduct_abmcts(prompt, difficulty):
  budget = abmcts.budget[difficulty]          # node generations: easy 6 / hard 12 / deep 20
  tree   = root(task)                          # root holds no answer, only children
  best   = None                                # highest-rated node so far
  for step in 1..budget:
     node   = SELECT(tree)                     # Thompson walk (below)
     alias  = BANDIT.pick(step)                # per-alias Thompson sample
     answer = generate(alias, node)            # ONE model call (fresh or refine)
     reward = judge_pairwise(answer, best)     # blind A/B -> Elo update -> rating in [0,1]
     child  = tree.add(node, answer, alias, reward)
     BACKPROP(child)                           # push reward up ancestors' value posteriors
     BANDIT.update(alias, reward)
     best   = argmax_rating(tree.nodes)
     if best survived early_stop_wins straight challenges: break
  return best.answer + receipt
```

### 4.1 SELECT — the adaptive "wider vs deeper"

Every node carries a **Gaussian value posterior** (mean, n) fed by back-propagated child
rewards, **plus one GEN arm** ("create a new child here") with its own posterior. SELECT
walks from the root: at each node, Thompson-sample a value from every child *and* the GEN
arm; take the max.

- **GEN wins at root** → generate a **fresh answer** (wider).
- **GEN wins at a solution node** → **refine that node's answer** (deeper).
- **A child wins** → descend into it and repeat.

GEN's prior starts optimistic (exploration); its posterior updates with the rewards of
children born at that node. Branching is therefore **unbounded and adaptive** — the
paper's core contribution. No fixed width, no fixed depth.

### 4.2 Multi-LLM bandit

- **Arm pool:** every alias that is (a) in `availability.yaml`-enabled providers and
  (b) health-OK if NIM (`model_health.yaml`, read fresh). Zen + Copilot arms are always
  in (reliable backends). Provider-blind — equal citizens.
- **Per-arm Gaussian posterior** on reward; Thompson sample each generation.
- **Capability priors** (cold-start fix for a 6–20 pull budget): prior mean by static
  rank — frontier 0.65 / strong 0.55 / base 0.45, prior weight n0 = 2. Capable models
  start favored; realized reward corrects.
- Failed generation (empty/timeout) → reward 0 for that arm — the bandit *learns* the
  flake instead of a health-gate hiding it.

### 4.3 Reward — pairwise judge → Bradley-Terry rating

- Each new answer judged **blind pairwise vs the current best** by an independent,
  cheap, non-thinking judge (`cop-haiku`; clean JSON — bench-proven). Random A/B order.
- Win/loss updates **Elo-style ratings** (K = 0.1) squashed to [0, 1]; a node's rating is
  its value signal. First node seeds the incumbent at 0.5.
- Pairwise kills the two failure modes we already hit: absolute-score drift and
  conductor self-bias.
- Judge unparseable → retry once → skip the update entirely (no reward noise).

### 4.4 generate(alias, node)

One model call through the router:
- **Fresh (root GEN):** answer the task.
- **Refine (node GEN):** task + parent answer + the judge's losing critique → improve it.
- Reasoning-model discipline (bench lessons, hard requirements): generous
  `gen_max_tokens` (4000), long `gen_timeout_s` (300) — **wait it out, never truncate
  mid-think**; last-block parsing; empty content = failed pull (reward 0), never a crash.

### 4.5 Stop & return

Stop at budget exhaustion **or** when the best node survives `early_stop_wins` (4)
consecutive challenges. Return the **highest-rated** node's answer.

## 5. Receipt

```json
{"mode": "tree", "difficulty": "...", "budget": 12, "generations": 9,
 "tree": [{"id": 1, "parent": 0, "alias": "zen-glm", "action": "fresh", "rating": 0.61}, ...],
 "bandit": {"zen-glm": {"pulls": 3, "mean_reward": 0.71}, ...},
 "best_node": 7, "best_rating": 0.83,
 "total_tokens": 41000, "est_cost": {...}, "wall_ms": 412000}
```

Full observability: tree shape, per-arm pulls/rewards, cost. Logged to
`logs/fusion-YYYYMMDD.jsonl` like v2.0/v2.1.

## 6. Math kept simple (pure stdlib, unit-testable)

- **Posteriors:** Gaussian with (mean, n); Thompson sample = `mean + gauss(0,1) * sigma0 / sqrt(n)`.
  `random` + `math` only — no numpy/scipy in the container or host.
- **Elo/BT update:** `expected = 1/(1+10**((rb-ra)/400))` scaled variant mapped to [0,1].
- Deterministic under `random.seed()` → tests assert exact search behavior.

## 7. Config (`fusion.yaml` — new `abmcts` block)

```yaml
abmcts:
  budget: {easy: 6, hard: 12, deep: 20}   # node generations per call
  judge: cop-haiku                        # pairwise, non-thinking, cheap
  gen_max_tokens: 4000
  gen_timeout_s: 300
  early_stop_wins: 4
  sigma0: 0.15                            # exploration width for Thompson samples
  prior_weight: 2                         # n0 pseudo-observations behind each prior
  prior_rank:                             # capability-only, provider-blind
    frontier: [cop-opus, cop-sonnet, zen-gpt, cop-gemini]
    strong:   [zen-glm, nim-qwen-max, nim-glm, nim-deepseek, nim-kimi, zen-deepseek]
    base:     [nim-mistral, nim-minimax, nim-nemotron, zen-free-deepseek, nim-qwen, nim-llama]
```

Any available alias **not listed** in `prior_rank` gets the `base` prior (pool is dynamic;
priors just seed). cop-gpt / cop-codex / cop-mini stay excluded — broken through litellm's
Copilot path.

## 9. Failure handling

- Generation empty/timeout → reward 0 pull, no node added, arm posterior learns.
- Judge unparseable after retry → skip update; search continues.
- All NIM unhealthy → pool = Zen + Copilot arms (still functional, per cost posture).
- Zero successful generations → return degraded receipt with error (never crash, never
  empty-string answer).
- Whole call bounded by `budget × gen_timeout_s` worst case; receipt always emitted.

## 10. Testing

Seeded `random` makes the search deterministic. Stub `call_model` (conftest pattern).
Key behaviors to pin:
- Thompson: arm with higher observed reward gets more subsequent pulls.
- Priors: with zero data, frontier-ranked arm is picked more often than base-ranked.
- SELECT: GEN fires at root when children stall (widen); descends into an improving
  child (deepen).
- BACKPROP: child reward shifts ancestor posteriors.
- Elo: win raises rating, loss lowers; ratings stay in [0,1].
- Early stop: incumbent surviving 4 challenges halts the loop.
- Empty generation → reward 0, no node, no crash.
- `parse_novel("[NOVEL TREE] x")` → `("x", "tree", None)`; `[NOVEL TREE DEEP]` → depth pin.
- Receipt schema complete.

## 11. Bench plan (after build)

3-way on `fusion/prompts.bench12.txt`: `[NOVEL]` greedy vs `[NOVEL TREE]` vs `cop-opus`
baseline, same pairwise-judge harness. Tree must beat greedy's $/point to earn a default
flip. Watch the **code category** — greedy's known weak spot (lost 7 vs 9).

## 12. Cost discipline & security

Bounded by budget; every generation itemized in the receipt. Reuses the Phase-1 master
key + `127.0.0.1` router; no new secrets, no new containers.
